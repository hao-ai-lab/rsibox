# verl Lessons

Lessons from building and running the `verl` live lab on 4x GB200 and multi-actor Ray clusters.

| Lesson | Do |
|---|---|
| `@ray.remote` on `AgentLoopWorkerTQ` replaces the class in its module with an `ActorClass` handle; inside the actor worker, cloudpickle builds a by-value copy of the class whose methods hold a fresh `__globals__` dict (`fn.__globals__ is not vars(module)`). A plain `LocalParticipant` swaps the dead class in `__ray_metadata__`, reports `committed`, and the actor keeps running old code. | Route all Ray actors through `core/livelab/ray_participants.py` (`RayActorParticipant` + `actor_view`), which registers a `<module>#actor` namespace over `type(host).__ray_actor_class__` and drops `zero_witness` on the dead module-level class body. |
| `verl/utils/import_utils.py:load_extern_object` loads `reward.custom_reward_function.path` via `spec_from_file_location` without adding it to `sys.modules`, keeping only the `compute_score` function object. Looking up the reward file in `sys.modules` fails in every `RewardLoopWorker`. | Resolve file-backed edits via `ray_participants.file_namespace(path)` (`co_filename` scan via `locate.all_objects()`), and fail closed if the same path was loaded into multiple disjoint globals dicts. |
| Restoring only `WorkerDict` trainer parameters (`S0`) leaves colocated or remote rollout engines serving trajectories from post-step weights (`t > 0`) and stale KV caches, breaking repeatability (`c0`) and fresh equivalence (`c3`). | Always couple trainer `S0` restoration with rollout weight synchronization (`checkpoint_manager.sleep_replicas()` + `checkpoint_manager.update_weights()`; `livelab/adapter/state.py:sync_rollout_weights`). |
| In multi-role Ray topologies (`TaskRunner` driver + `RewardLoopWorker` + `AgentLoopWorkerTQ` + `WorkerDict`), no single actor imports every module (`RewardLoopWorker` never imports Megatron; `WorkerDict` never loads the custom reward script). Asking `Session` to fingerprint all modules on every actor fails immediately at startup (`module not loaded`). | Fingerprint each actor over the subset of tracked modules actually loaded in that actor (`ray_participants._fingerprint_modules`), and pre-check `ray_participants.unloaded(participants, plan)` before `Session.install` so an edit nobody loaded is refused instead of silently abstained everywhere. |
| Shared NFS multiplies Python import and dataset tokenization latency across ~20 Ray worker processes (`1,022 s` launch-to-first-step on NFS vs. `187 s` on parallel storage), while copying a venv to a new local path invalidates path-keyed `torch.compile` and Triton caches (`57 s -> 105 s` vLLM boot). | Keep the job alive across edits (`28-39 s` live step verdict), or stage local environments at a stable path so `torch.compile` and Triton caches hit. |
| `verl`'s built-in `timing_s/step` wraps `on_step_begin()`, so it includes the wall-clock time the gate spent waiting for the next client request. | Read `verdict_s` and `install_s` from the gate's receipt (or steps 2+ of a multi-step request), never `timing_s/step` on step 1 after an idle wait. |
| On shared multi-tenant Ray clusters, `ray.init(address="auto")` schedules `RewardLoopWorker` and `WorkerDict` actors onto other users' nodes unless placement confinement is enforced. | Confine Ray resources to allocated node IDs or start an isolated head (`--head --num-cpus=... --num-gpus=4`) inside the job allocation. |
| `rollout.full_determinism=True` seeds every request on a replica with the same vLLM seed (`vllm_async_server.generate`: `replica_rank + rollout.seed`), so a prompt's `n` samples collapse to one text per replica and GRPO advantages are all zero; which replica serves a request (least-loaded routing) then decides its text, so repeated steps still differ. Our 2026-11-19 4x GB200 run trained six steps with `advantages/max == 0`. | Seed each request from `(sample_index, session_id)` inside the agent-loop actors (`livelab/adapter/determinism.py`, `FASTRSI_RL_SEED_PER_SAMPLE=1`); keep `full_determinism` on for batch-invariant kernels. |
| With `full_determinism`, vLLM 0.31 on torch 2.13 dies at boot when CUDA graphs and `torch.compile` are on: Inductor's autotune `benchmark_gpu` refuses to run in deterministic mode (`InductorError ... deterministic mode of Inductor`). | Run deterministic jobs with `rollout.enforce_eager=True`, OR for `FSDP + CUDA graphs` set `VLLM_BATCH_INVARIANT=1` + `enforce_eager=False` + `full_determinism=False` + `FASTRSI_RL_SEED_PER_SAMPLE=1` (eager FSDP steps took 102–117 s vs 52 s; `VLLM_BATCH_INVARIANT=1` FSDP CUDA-graph conformance passed **`11/11`** bit-exact [`5,792.1 s`, `gen 4.18 s`, `0 MiB × 4`], whereas Megatron-Core with `actor...attention_backend=unfused` + `deterministic_mode=True` still exhibits `~1e-4` `pg_loss` variance with `ref...attention_backend` remaining `flash`). |
| The FSDP config has no `actor.megatron` section; reading it unconditionally (`_batch_sizes`) raised on every gate request of an FSDP job. | Branch on `actor.strategy`; the model-parallel size is 1 unless the strategy is Megatron. |
| Restoring trainer and rollout weights but not the dataloader makes every check train on the next prompt batch, so no two checks compare the same inputs. | Snapshot `train_dataloader.state_dict()` at `on_init_end` and load it back (and drop the live iterator) in the coupled `S0` restore. |
| `srun` forwards its stdin to the task: a `srun ... bash -c` line inside a script fed to a remote `bash -s` swallows the rest of the script. | Launch node-side steps with `< /dev/null` and keep the gate client on a shared file system, where it needs no RPC to the node. |
