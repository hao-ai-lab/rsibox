# TensorRT-LLM (PyTorch backend) lessons

Verified pitfalls discovered during live NVIDIA B200 bring-up on `TensorRT-LLM 1.0.0rc6` (`backend="pytorch"`) and the rules that prevent them.

| Pitfall | Rule | Evidence |
|---|---|---|
| By default, `tensorrt_llm.LLM` spawns a separate MPI worker process via `GenerationExecutorProxy` even for `tensor_parallel_size=1`, so hot-swapping modules in the caller process never reaches `PyExecutor` or `TorchSampler`. | Set `TLLM_WORKER_USE_SINGLE_PROCESS=1` in the spawned RSIBox worker process before importing `tensorrt_llm` so `GenerationExecutor.create()` instantiates `GenerationExecutorWorker` and `PyExecutor` in-process. | `tensorrt_llm/executor/executor.py: GenerationExecutor.create` (`enable_worker_single_process_for_tp1`); verified live on `1x B200` (`type(llm._executor) == GenerationExecutorWorker`). |
| For greedy decoding (`temperature=0.0`, no logprobs), `TorchSampler._process_requests` takes an inline `fast_path` (`torch.argmax(logits, dim=-1)`) and bypasses `greedy_search_sampling_batch`, and the line `next_tokens = torch.argmax(logits, dim=-1)` appears twice in `sampler.py`. | Target `TorchSampler._process_requests` with a unique multi-line anchor (`self._apply_embedding_bias(...)` + `torch.argmax(...)`) for greedy sampler edits rather than assuming `greedy_search_sampling_batch` executes. | `tensorrt_llm/_torch/pyexecutor/sampler.py:464-472`; verified `17` witness calls on `1x B200` for a 2-prompt × 16-token greedy batch. |
| TensorRT-LLM `1.0.0rc6` exposes `tensorrt_llm._torch.virtual_memory` (`CudaVirtualMemoryManager`), but default PyTorch-backend weights and KV pools are NOT wrapped in `virtual_memory.scope(...)`, so `release_with_tag("kv_cache")` / `release_with_tag("weights")` release `0` blobs by default. | Release disposable KV cache VRAM via `kv_cache_manager.impl.release_pools()` and restore via `kv_cache_manager.impl.allocate_pools(False)` followed by refreshing `kv_cache_pool_pointers` and `kv_cache_pool_mapping`. | `1x B200` probe (`2026-11-24`): `release_with_tag` returned `0` blobs, whereas `release_pools()` freed `24,168.0 MiB` (`46,283.94 -> 22,115.94 -> 46,283.94 MiB`) with bit-exact post-restore generation and live edit. |
| Importing `tensorrt_llm` on a CPU-only node without `libcuda.so.1` fails immediately during `tensorrt_llm.bindings` import. | Keep all `tensorrt_llm` and `torch` imports strictly lazy inside worker subprocess execution (`agent.py` `_build_engine` / `_run_engine_generate`), never at top level of `adapter/__init__.py`, `lab.py`, `toy_lab.py`, or `snapshot_hooks.py`. | Verified by `rsibox doctor` (`0` GPU import violations) and `LazyImportTest.test_adapter_imports_stay_gpu_free`. |
