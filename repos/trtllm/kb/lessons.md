# TensorRT-LLM (PyTorch backend) lessons

Verified pitfalls discovered during live NVIDIA B200 bring-up on `TensorRT-LLM 1.0.0rc6` (`backend="pytorch"`) and the rules that prevent them.

| Pitfall | Rule | Evidence |
|---|---|---|
| By default, `tensorrt_llm.LLM` spawns a separate MPI worker process via `GenerationExecutorProxy` even for `tensor_parallel_size=1`, so hot-swapping modules in the caller process never reaches `PyExecutor` or `TorchSampler`. | Force `TLLM_WORKER_USE_SINGLE_PROCESS="1"` in the spawned RSIBox worker process before importing `tensorrt_llm` so `GenerationExecutor.create()` instantiates `GenerationExecutorWorker` and `PyExecutor` in-process, and refuse `tensor_parallel_size != 1` in `TrtllmLab`. | `tensorrt_llm/executor/executor.py: GenerationExecutor.create` (`enable_worker_single_process_for_tp1`); verified live on `1x B200` (`11/11` conformance). |
| For greedy decoding (`temperature=0.0`, no logprobs), `TorchSampler._process_requests` takes an inline `fast_path` (`torch.argmax(logits, dim=-1)`) and bypasses `greedy_search_sampling_batch`, and the line `next_tokens = torch.argmax(logits, dim=-1)` appears twice in `sampler.py`. | Target `TorchSampler._process_requests` with a unique multi-line anchor (`self._apply_embedding_bias(...)` + `torch.argmax(...)`) for greedy sampler edits rather than assuming `greedy_search_sampling_batch` executes. | `tensorrt_llm/_torch/pyexecutor/sampler.py:464-472`; verified `17` witness calls on `1x B200` for a 2-prompt × 16-token greedy batch. |
| TensorRT-LLM `1.0.0rc6` exposes `tensorrt_llm._torch.virtual_memory` (`CudaVirtualMemoryManager`), but default PyTorch-backend weights and KV pools are NOT wrapped in `virtual_memory.scope(...)`, so `release_with_tag("kv_cache")` / `release_with_tag("weights")` release `0` blobs by default; C++ `allocatePools(bool useUvm)` takes `useUvm=False`, and `enable_block_reuse=True` would keep stale prefix-tree pointers across pool release. | Release disposable KV cache VRAM via `kv_cache_manager.impl.release_pools()` (failing closed if `enable_block_reuse=True`, clearing `kv_cache_pool_pointers` / `kv_cache_pool_mapping`) and restore via `kv_cache_manager.impl.allocate_pools(False)` followed by refreshing pool pointers/mapping and failing closed + poisoning if pool pointers shift without `"cuda_graphs"` recapture. | `1x B200` probe (`2026-11-24`): `release_with_tag` returned `0` blobs, whereas `release_pools()` freed `24,168.0 MiB` (`46,283.94 -> 22,115.94 -> 46,283.94 MiB`) with bit-exact post-restore generation and live edit. |
| Importing `tensorrt_llm` on a CPU-only node without `libcuda.so.1` fails immediately during `tensorrt_llm.bindings` import, and calling `importlib.util.find_spec("tensorrt_llm._torch...")` in the host process executes `tensorrt_llm/__init__.py`. | Keep all `tensorrt_llm` and `torch` imports strictly inside worker subprocesses (`agent.py`), fetch tracked base module sources from rank 0 over RPC (`read_source`), and locate the overlay `src_dir` via top-level `find_spec("tensorrt_llm")` only. | Verified by `rsibox doctor` (`0` GPU import violations) and `LazyImportAndConfigTest.test_adapter_imports_stay_gpu_free`. |
| In `fresh_check` subprocesses loading `tensorrt_llm` through a symlink `PackageOverlay`, `libth_common.so` C++ `atexit` static destruction (`AttentionOp` -> `CublasMMWrapper::~CublasMMWrapper`) can dereference torn-down CUDA state and exit with `SIGSEGV` (`rc=-11`) AFTER `engine.shutdown()` and `FRESH {...}` stdout output complete. | In `agent.py` `"fresh"` mode for real TensorRT-LLM, call `engine.shutdown()`, flush `stdout`/`stderr`, and exit cleanly via `os._exit(0)` to avoid the `1.0.0rc6` C++ static destructor race. | `1x B200` `c3_fresh_equivalence` diagnosis (`2026-11-24`): `FRESH {...}` matched base bit-exact before `SIGSEGV` in `CublasMMWrapper::~CublasMMWrapper`; `os._exit(0)` resolved `c3` to `11/11` real GPU conformance pass. |
