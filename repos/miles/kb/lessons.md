# Lessons (`miles`)

| Observation | Rule in `repos/miles/` | Evidence |
|---|---|---|
| `@ray.remote` replaces `MegatronTrainRayActor` and rollout actor classes in `sys.modules` with an `ActorClass` handle, while each actor process runs a deserialized by-value class copy over its own globals dict. A plain `LocalParticipant` commits and leaves the old method running. | Route all actor participants through `core/livelab/ray_participants.py` (`actor_view` + `RayActorParticipant`), primed before `Session` base fingerprinting via `serve_actor` (`adapter/gate.py`). | `test_ray_participants.py` (`4 != 40` without `actor_view`); `test_rollout_actor_method_swap_reaches_deserialized_actor_copy`. |
| In `--fully-async` mode (`miles/rollout/fully_async_rollout.py`), `DefaultDataBuffer` filters groups by `weight_version` (`--max-weight-staleness`), not by code version. After a live reward or rollout edit, pre-edit groups sitting in the buffer are still within weight staleness and contaminate post-edit training steps. | Quiesce rollout via `pause_generation` + `flush_cache`, bump `EpochDataBuffer.code_epoch` on every `install` and `uninstall`, and evict buffered groups with `epoch < code_epoch` (`stale_code_epoch`). | `test_epoch_data_buffer_evicts_pre_edit_trajectories_on_epoch_advance` and `test_async_mode_quiesces_rollout_controller_and_drains_stale_epoch`. |
| Restoring `S0` weights on trainer actors alone leaves SGLang rollout servers holding post-step weights from the previous check, breaking `c0_repeatable` and `c4_uninstall`. | Couple trainer `S0` restoration with an immediate `update_weights` broadcast and `flush_cache` (`CoupledWeightReset.restore_and_sync` in `adapter/state.py`). | `test_coupled_weight_reset_syncs_rollout_weights_with_restored_trainer_s0` (`rollout` stays at `99 != 4` when `broadcast_rollout=False`). |
| Multi-role Ray jobs import disjoint module subsets (`RolloutExecutor` never imports Megatron trainer internals, and trainer actors never load custom rollout-only `.py` files). Calling `LocalParticipant.fingerprint` with the union of session modules fails with `module not loaded`. | Scope each actor's `fingerprint` payload in `serve_actor` (`adapter/gate.py`) to the modules and `file_namespace` files loaded in that actor process, while checking `ray_participants.unloaded(participants, plan)` on `install` so edits to files loaded by *no* actor still fail closed (`unloaded_module`). | `test_rollout_actor_method_swap_reaches_deserialized_actor_copy` and `test_unloaded_module_or_file_fails_closed_instead_of_silent_noop_commit`. |
| GRPO group-relative advantages subtract the within-group baseline, so an additive constant reward edit (`r + c`) cancels out identically in the advantage vector even though the edited reward function ran (`proven = True`). | Design visible reward probes and golden tests with scale or prompt-dependent reward changes rather than constant shifts. | Caught while testing `CUSTOM_REWARD` in `test_custom_reward_file_without_sys_modules_swaps_and_undoes_live`. |
| Pure-class `@ray.remote` actors that reference no module-level helpers are unpickled by cloudpickle without importing their defining module into the Ray worker's `sys.modules`, causing `ray_participants.actor_view` (`sys.modules.get(own.__module__)`) and `_loaded` to miss the actor. | Import `type(host).__ray_actor_class__.__module__` on first `serve_actor` entry when absent from `sys.modules` (`adapter/gate.py`). | `test_real_ray_actors_swap_and_undo_through_miles_step_gate` under Ray 2.x (failed with `unloaded_module` before the `import_module` guard). |
| `MegatronTrainRayActor` holds `self.weights_backuper` (`weights_backuper._weights_backup["actor"]`) separate from `actor.model`; restoring `S0` on `actor.model` alone lets `weights_backuper.restore("actor")` overwrite restored `S0` weights with stale post-step copies on the next train/sync cycle. | Sync `actor.weights_backuper.backup("actor")` right after `MState.Snapshot.restore()` + `MState.zero_new_state()` (`sync_weights_backuper` / `post_restore` in `adapter/state.py`). | `test_sync_weights_backuper_prevents_stale_backup_reversion_after_s0_restore` and real `2× B200` `parity_rm` genuine-gradient `S0` replay (`weights_changed_from_s0: true`, `bit_exact_undo_on_same_rollout: true`). |
| Ray's `#actor` synthetic view (`core/livelab/ray_participants.py`) compiles and evaluates module ASTs under the synthetic globals dict, so 3-dot relative imports (e.g. `from ...utils.profile_utils import TrainProfiler` in `slime.backends.megatron_utils.actor`) raise `ImportError: attempted relative import beyond top-level package` if targeted directly via `#actor`. | Target subpackage modules without deep relative imports (`slime.backends.megatron_utils.model`) for dead/cold-path actor probes (`c10_not_proven`), and avoid 3-dot relative imports inside `#actor`-targeted modules. | Observed in Wave 10 `RealSlime11Lab` `c10_not_proven` (`actor.py:29` failed on `...utils`, resolved cleanly via `slime.backends.megatron_utils.model`). |
| Under Ray `2.54.0` (`slimerl/slime:latest`), C++ `OpenTelemetryMetricRecorder::Start()` spawns a background `OtlpGrpcMetricExporterOptions` thread that calls `getenv()` concurrently during Python/Torch initialization, causing intermittent `SIGSEGV` in `InfoActor` or `Lock`; Ray C++ `RayConfig` reads **lowercase** `RAY_enable_open_telemetry` / `RAY_enable_metrics_collection` (and `ray.init(_system_config=...)`), ignoring uppercase `RAY_ENABLE_OPEN_TELEMETRY=0`. | Set both `RAY_enable_open_telemetry=0` and `RAY_enable_metrics_collection=0` alongside `_system_config={"enable_open_telemetry": False, "enable_metrics_collection": False}` in `ray.init(...)` for repeated Ray cluster respawn harnesses (`c3`/`c8`). | Reproduced on `b200` in `InfoActor` and `Lock` during repeated Ray cluster respawns; verified clean actor ping/shutdown (`RAY_CLEAN_OK`) in Ray `2.54.0` with lowercase flags + `_system_config`. |
