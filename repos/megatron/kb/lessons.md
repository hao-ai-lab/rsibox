# Lessons

Pitfall, rule, evidence. Edited in place; generic and public-safe. Engine-agnostic harness and
replay rules live in `docs/lessons.md`.

| Pitfall | Rule | Evidence |
|---|---|---|
| Killing the launcher's process group left torchrun's workers alive and holding GPU memory; the next start found the GPUs busy. | Kill a training job by its process tree (PIDs from `/proc`), children first; torchrun starts each worker in a session of its own. | Our 2026-11-07 lab smoke: two workers survived with 6 GiB each after the group kill; `conformance_lab._descendants` fixed it and c8's four respawns then started clean. |
| A loss gate calibrated on a run whose loss spikes rejects every edit: nondeterministic bf16 reductions grow through the spikes. | Pick the workload's learning rate so the base repeats itself within the gate before the first edit; measure base against base. | Qwen3-14B architecture from random init: at lr 3e-4 three identical 8-step checks differed by up to 4% in loss at step 8; at 3e-5 by 0.15%. |
| On a node shared with other jobs, the median step time of the same code spread 6% across checks, larger than most real gains. | Decide speed by paired A/B in the same warm job (candidate, base, candidate, base; the lab swaps in 0.05 s) and use the fastest steps of each check. | Step times of one check ranged 4.34-5.38 s; fastest-3 spread 4% across three base checks. |
| The first train step after start-up pays 6-11 s of lazy setup (NCCL communicators, Adam state, kernel choice) and Megatron's import 16-31 s from a network file system. | A restart costs about a minute before the first useful step even for a 2-layer model: keep the process, change the code. | `costs.md`, restart ladder. |
| With Transformer Engine layers, Megatron's own `ColumnParallelLinear` backward runs only for the LM head; edits there are proven (witness > 0) but move the step by well under 1%. | Read the profile against the layer specs before choosing where to edit: the 40 transformer layers' GEMMs and sequence-parallel collectives are inside TE. | Hill-climb iterations 4, 7, 8 (2026-11-07): +0.2%, +0.88%, +0.26% paired. |
| An edit that also touched a path the configuration never runs (the fused cross-entropy, off here) left a zero witness, and the whole transaction was not proven. | Edit only live paths; a zero witness on any changed function rejects the edit, by design. | Hill-climb iteration 1: `calculate_logits_max` 128 calls per rank, the fused `forward` 0. |
| A sync that replaced a running job's shell script on the shared file system killed the job's shell after its main process ended ("Stale file handle"): bash reads scripts as it runs them. | Wrap launch scripts in `{ ...; exit; }` so bash reads them whole before running. | Our 2026-11-07 hill-climb lab: the job ended with rc 2 and no end stamp; its GPUs were already free. |
| A launch script run inside a 0-GPU scheduler task (Ray `num_gpus=0`) saw no GPUs: the scheduler sets `CUDA_VISIBLE_DEVICES` to empty, and the script relied on inheriting it. | A launch script that runs under a scheduler task sets `CUDA_VISIBLE_DEVICES` itself; validate a staged multi-node script single-node first. | Our 2026-11-07 single-node run of the staged 2-node script: "No CUDA GPUs are available" on all 4 ranks after 67 s; it would have failed the same way on two nodes. |
| A gain decided on the mean of two A/B pairs was one pair hit by outside load (ratios 1.23 and 1.016); re-measured with 4 pairs the edit failed the gate. | Decide on the median of the pair ratios, require every pair faster, and re-measure near-misses and large surprises with 4 pairs before trusting them. | Hill-climb iteration 27 and its re-measure 35. |
| Two independent 4-pair A/B samples of the same edit on a shared node gave medians of +2.1% and -3.0%. | Do not relax a keep rule after seeing a near-miss; take another independent sample instead, and report gains from a final paired confirmation of the whole kept set. | Hill-climb iteration 57, re-measured as 59 and 60 (2026-11-07). |
| A second hill-climb started with a fresh history, and its first candidate was an edit that had already crashed the other lab twice; on two nodes (no automatic respawn) it ended the session an hour early. | Share the record of failed and crashed candidates across every harness on the same engine, and refuse a known crasher before it reaches the lab. | 14B iterations 68 and 95, then the first 2-node candidate (2026-11-07). |
| A six-point NCCL sweep was launched as six 2-node training restarts (about 160 s each) without first asking what each change costs and whether a cheaper probe answers the same question; NCCL reads its algorithm and protocol once per process, so every point was a restart. | Before a new kind of experiment, the online toolsmith states its restart class and predicted cost from `costs.md`, and looks for a cheaper probe first: here a collective microbenchmark (same message sizes and groups, a fresh tiny process per setting, seconds each), then restarts only for promising settings. To make such changes live, load an NCCL tuner plugin at start that can pick algorithm and protocol per collective at run time. | 2-node sweep, 2026-11-07: 4 settings within -4%..+1% of the repeat baseline. |
| A single baseline was compared with an estimate before its run-to-run noise was known: two runs of the same 2-node config an hour apart took 11.57 and 8.85 s per step. | Measure the noise of a new configuration (at least two runs) before comparing it with anything. | 2-node baseline and sweep repeat, 2026-11-07. |
| A 71 s collective microbenchmark ranked five NCCL settings like the 17.4 min training sweep for four of them, but missed a +27% regression (NVLS with cuMem) that only showed in real training. | Screen restart-tier settings with the cheap probe, then confirm the chosen one with a single restart; never ship a setting on the probe alone. | 2-node sweep and probe, 2026-11-07 (`costs.md`). |
| Over 114 hill-climb iterations, installs took 17 s in total (0.10 s median) while deciding took 4.2 h of 8-step A/B checks (about 195 s per candidate): the live lab removed the restart, and measurement became the cost. | Decide with A and B alternated per step inside one check (a swap costs 0.03-0.1 s), so outside load cancels within one check instead of across four. | 14B hill-climb records, 2026-11-07. |
| The largest wins of the night (fused weight-gradient accumulation, DDP bucket size) were launch flags that a function swap cannot reach, and the developer agent could not ask for them. | Offer config and flag changes to the agent as a priced action: a restart from the in-memory start state in a pre-imported (forked) process, so it costs the build and first step, not the 16-85 s import. | Iterations 12 and 65; 2-node sweep and A/B. |
| `--ddp-bucket-size 4e8` looked like the only real win of the NCCL/DDP sweep (-3.6% step time, then up to +40% in the lab with the kept set), but its loss left the base curve from step 3 (0.7% after two updates, 3x at step 6) with no edits at all, while each setting repeated itself to 1e-3. With DP 2 the gradient sum is a single a+b, so a bucket size alone should not change it. | Never take a throughput gain from a config change without the loss gate: a faster setting can be faster because it is wrong (suspect: parameter all-gather overlap with one huge bucket, forward using parameters before their gather finishes; not verified). Attribute in the lab: no edits, each edit, all edits, under the suspect setting. | 2-node lab phases labC-1..5, 2026-11-07 (`costs.md`). |
| Each kept edit moves loss a little; the gate compares against the original base, so kept edits use up the tolerance for later candidates (step-8 differences 3e-3 after one kept numeric change, against 7e-4 base vs base). | Prefer bit-exact or reorder-only edits early; account for the drift budget when keeping an edit that changes numerics. | Hill-climb iterations 30-32 failed the gate at 5.6-6.9e-3 on top of iteration 27. |
| Adam's moments do not exist before the first optimizer step, so a snapshot taken at start cannot restore them. | Take the start state before any step, warm up, put it back and zero the state the warm-up created (a fresh Adam's zeros); report any other key instead of zeroing it. | TE FusedAdam keeps moments in `.state` (created at step 1) and its step count in `param_group["step"]`; `test_pieces.py` start-state case fails without the zeroing. |
| Three of six recent upstream Megatron-LM PRs that touch this workload's code change constructors, add fields or remove definitions; the live swap refuses them. Two more install cleanly but never run here. | Replay real PRs with a restart tier ready next to the swap: send refused PRs to a fresh job with the PR's modules loaded at import. Count a zero witness as "not reached", never as a replay. | `examples/upstream-replay/`, 2026-11-07. |
| Two upstream diffs applied "successfully" with fuzz 3 but put hunks in the wrong function; the result did not compile. | Engine-agnostic rule moved to `docs/lessons.md` (lesson 4): check hunk function placement and compile on CPU after any fuzzy apply. | PRs 8246 and 8524 in `examples/upstream-replay/` (caught in 0.1 s by `py_compile`). |
| Two copies of the same training job on one node differed by 28% (0.72x), because GPUs 2,3 sit on the second CPU socket and the processes were not bound. | Bind each job's CPUs to its GPUs' socket from the start. Before comparing jobs on different GPUs, measure their speed ratio with a no-op run and repeat that measurement regularly. | `costs.md`, CPU socket placement. |
| A harness killed while it held the lock on the restart GPUs left the lock behind, plus a candidate job waiting for commands; the next user waited 22 minutes. | Engine-agnostic rule moved to `docs/lessons.md` (lesson 7): record the holder's PID in the lock, break locks whose process is gone, and give every started candidate job an explicit exit. | 2026-11-07 hill-climb, restart-GPU lock. |
| Given a priced menu (live swap about 250 s to decide, flag restart about 225 s, each with its measured restart overhead), Codex proposed flag restarts for launch-config ideas and live swaps for code ideas in all 24 real proposals, but 3 of its 4 flags failed here: `--gradient-accumulation-fusion` at the first step (no apex for the LM head's non-TE linear), the precision-aware optimizer in lab setup, the TE cross-entropy fusion in Megatron's argument check. | List a flag in the agent's menu only after one restart with it has reached a train step on this build, mark the rest "not usable here" with the reason, and show the agent each flag's measured result in this lab next to the price. | 2026-11-07 hill-climb, 42 rows; the first failure 58 s after the request. |
| A harness killed in the middle of an evaluation left the candidate's swap installed in the base lab; undoing it hours later also undid the two kept swaps installed after it (undo goes from a transaction to the newest). | Engine-agnostic rule moved to `docs/lessons.md` (lesson 16): stop a harness only between evaluations (`STOP` file) and reconcile the lab's live transactions against the kept record at start. | 2026-11-07 hill-climb, transaction installed 14:10, found 15:16. |
