# Lessons

Pitfall, rule, evidence. Edited in place; generic and public-safe.

| Pitfall | Rule | Evidence |
|---|---|---|
| Killing the launcher's process group left torchrun's workers alive and holding GPU memory; the next start found the GPUs busy. | Kill a training job by its process tree (PIDs from `/proc`), children first; torchrun starts each worker in a session of its own. | Our 2026-11-07 lab smoke: two workers survived with 6 GiB each after the group kill; `conformance_lab._descendants` fixed it and c8's four respawns then started clean. |
| A loss gate calibrated on a run whose loss spikes rejects every edit: nondeterministic bf16 reductions grow through the spikes. | Pick the workload's learning rate so the base repeats itself within the gate before the first edit; measure base against base. | Qwen3-14B architecture from random init: at lr 3e-4 three identical 8-step checks differed by up to 4% in loss at step 8; at 3e-5 by 0.15%. |
| On a node shared with other jobs, the median step time of the same code spread 6% across checks, larger than most real gains. | Decide speed by paired A/B in the same warm job (candidate, base, candidate, base; the lab swaps in 0.05 s) and use the fastest steps of each check. | Step times of one check ranged 4.34-5.38 s; fastest-3 spread 4% across three base checks. |
| The first train step after start-up pays 6-11 s of lazy setup (NCCL communicators, Adam state, kernel choice) and Megatron's import 16-31 s from a network file system. | A restart costs about a minute before the first useful step even for a 2-layer model: keep the process, change the code. | `costs.md`, restart ladder. |
| With Transformer Engine layers, Megatron's own `ColumnParallelLinear` backward runs only for the LM head; edits there are proven (witness > 0) but move the step by well under 1%. | Read the profile against the layer specs before choosing where to edit: the 40 transformer layers' GEMMs and sequence-parallel collectives are inside TE. | Hill-climb iterations 4, 7, 8 (2026-11-07): +0.2%, +0.88%, +0.26% paired. |
| An edit that also touched a path the configuration never runs (the fused cross-entropy, off here) left a zero witness, and the whole transaction was not proven. | Edit only live paths; a zero witness on any changed function rejects the edit, by design. | Hill-climb iteration 1: `calculate_logits_max` 128 calls per rank, the fused `forward` 0. |
| A sync that replaced a running job's shell script on the shared file system killed the job's shell after its main process ended ("Stale file handle"): bash reads scripts as it runs them. | Wrap launch scripts in `{ ...; exit; }` so bash reads them whole before running. | Our 2026-11-07 hill-climb lab: the job ended with rc 2 and no end stamp; its GPUs were already free. |
| A launch script run inside a 0-GPU scheduler task (Ray `num_gpus=0`) saw no GPUs: the scheduler sets `CUDA_VISIBLE_DEVICES` to empty, and the script relied on inheriting it. | A launch script that runs under a scheduler task sets `CUDA_VISIBLE_DEVICES` itself; validate a staged multi-node script single-node first. | Our 2026-11-07 single-node run of the staged 2-node script: "No CUDA GPUs are available" on all 4 ranks after 67 s; it would have failed the same way on two nodes. |
| A gain decided on the mean of two A/B pairs was one pair hit by outside load (ratios 1.23 and 1.016); re-measured with 4 pairs the edit failed the gate. | Decide on the median of the pair ratios, require every pair faster, and re-measure near-misses and large surprises with 4 pairs before trusting them. | Hill-climb iteration 27 and its re-measure 35. |
| Two independent 4-pair A/B samples of the same edit on a shared node gave medians of +2.1% and -3.0%. | Do not relax a keep rule after seeing a near-miss; take another independent sample instead, and report gains from a final paired confirmation of the whole kept set. | Hill-climb iteration 57, re-measured as 59 and 60 (2026-11-07). |
| Each kept edit moves loss a little; the gate compares against the original base, so kept edits use up the tolerance for later candidates (step-8 differences 3e-3 after one kept numeric change, against 7e-4 base vs base). | Prefer bit-exact or reorder-only edits early; account for the drift budget when keeping an edit that changes numerics. | Hill-climb iterations 30-32 failed the gate at 5.6-6.9e-3 on top of iteration 27. |
| Adam's moments do not exist before the first optimizer step, so a snapshot taken at start cannot restore them. | Take the start state before any step, warm up, put it back and zero the state the warm-up created (a fresh Adam's zeros); report any other key instead of zeroing it. | TE FusedAdam keeps moments in `.state` (created at step 1) and its step count in `param_group["step"]`; `test_pieces.py` start-state case fails without the zeroing. |
