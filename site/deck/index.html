RSIBox

Keep the weights warm while AI agents rewrite the engine.

A live hot-reload sandbox and multi-agent GPU pool for production ML engines. Agents edit vLLM, SGLang, Megatron-LM and seven more engines in place, and see the result in milliseconds instead of minutes. Built at Hao AI Lab, v0.0.2.

RSI is bottlenecked by system overhead

RSI, recursive self-improvement, means AI agents improving the software that runs AI. Two measurements show where an agent’s clock goes. It spends most of a run waiting on evaluation, not generating tokens, so a faster model barely helps. And most of each evaluation is the engine starting up again.

1Evaluation, not the model, sets the pace

2Inside each evaluation, start-up dominates

What you’re seeing: on the left, a real 6-hour vLLM run replayed with faster models: the run barely gets shorter. On the right, one check on each engine: rust is the engine starting up, blue is the test itself. Try: pick a model speed, switch to share of the check, or click an engine to see where its start-up goes.

But most system overhead can be mitigated

None of the start-up depends on the line that changed. Testing a one-line change to vLLM’s scheduler takes 228 s with a restart. Keep the tuned kernels, the weights, the CUDA graphs and the process warm, and the same check takes 24 s. Shrink the test to a small probe and it takes 2.4 s.

Swap only what changed. Keep everything else running.

An agent doing RSI proposes one change after another. rsibox ships each change into the running engine and swaps only the code it touches. Weights, compiled kernels, CUDA graphs and live requests stay where they are.

Life of a live edit

      
Follow one rsibox install from the agent to four GPUs. The engine keeps stepping the whole time. Before changing anything, each rank writes down how to reverse it, so rsibox uninstall can put the exact original code back in about 0.05 s, with no restart. Failures leave nothing half done: one refusing rank aborts the edit everywhere, and a crashed worker is replaced by a warm standby.

    RSIBox architecture
    
    
    An engine is boxes inside boxes, and restarting a box throws away everything inside it. RSIBox restarts the smallest box that holds the change. Its four layers split that job: one decides, one swaps, one keeps the GPU state warm, one knows each engine.

    Verified by a model checker and a test suite
    
    
    The core protocols are written in TLA+, a language for describing a protocol precisely enough that a model checker can try every ordering of events and look for one that breaks a rule. Every engine adapter must then pass the sandbox verification suite before its numbers count.

    RSIBox cuts edit-and-test time by 87–97%
    
    
    Testing one edit with a full check takes 87–97% less time than restarting first, across serving, training, video generation and RL post-training. A targeted probe cuts it by up to 99%. In races with the same agent, the shorter loop gets it to the best result sooner.

    Many agents, a few warm GPUs
    
        
    An agent spends most of its time thinking, not testing. SandboxPool leases each check a warm GPU for under a second, so one GPU can serve a whole team. Waiting agents gain priority so nobody starves, and an agent that keeps crashing workers is cut off from more than one GPU. Next: run it inside serverless and microVM sandboxes.
